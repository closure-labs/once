# Once v0.5.0

Once v0.5.0 adds portable signed check reuse between fresh GitHub runners.
A protected producer builds once, exports native Nix trace evidence, and uploads
a small artifact. A consumer verifies that evidence against an immutable policy
and can skip an accepted check without restoring its outputs.

## Changes

- Add full Nix `name:base64` public keys through the optional schema-1
  `trust.public_keys` array. Existing local policies remain compatible.
- Verify Ed25519 signatures using the native Nix fingerprint format for upstream
  2.35.3 and Determinate Nix 3.23.3; signer labels alone cannot authorize reuse.
- Add `once export INSTALLABLE --output DIRECTORY`,
  `once check INSTALLABLE --trace-bundle DIRECTORY`, and
  `once bundle-key INSTALLABLE`. Bundles contain signed trace evidence without
  output NARs, private keys or copied store databases.
- Resolve native dependency mappings only from verified bundle evidence. A
  missing bundle or incomplete dependency graph gives `MISS`, including on a
  runner that already has local trace state.
- Add `producer-workflow`, `producer-branch` and `trace-bundle` Action inputs,
  plus `cache-hit`, `decision` and `bundle-id` outputs. The publish Action exports
  only after protected-branch push builds; successful-run artifacts expire after
  30 days by default.
- Resolve the effective store before assigning local trust, disable IFD during
  inspection, preserve existing lock files, and match trace records by identity.
- Pin optional Action installs and CI/release installs to Determinate Nix 3.23.3,
  asserting upstream 2.35.3. Reuse bootstrap packages through the explicit signed
  Once Cachix cache, falling back to building the pinned Action source.

Portable checks must embed their policy's `policy_version` with `mkOnceCheck`.
The first supported target is static content-addressed checks on `x86_64-linux`,
with one accepted signature and `ia_mode = "warn"` explicitly disclosing trust in
input-addressed dependencies. General availability of the Nix distribution does
not make `ca-derivations` a stable feature.

## Adoption and validation

Use the [GitHub Action guide](../github-action.md) and its linked producer and
consumer examples. Pin both Once and policy revisions to full commits; keep the
workflow, accepted public keys and producer branch protected. Consumers need
only read permissions and no signing credentials. Only a genuine `MISS` should
fall back to the normal build; verification and transport errors fail the job.

CI includes native signature fixtures, fresh-store resolution, output-absence
checks, signature and identity tampering, incomplete evidence, revoked keys,
source/policy invalidation, artifact expiration, and producer-run filtering.
The fresh-store proof runs in a pinned privileged community Nix 2.35.3 container
because disposable chroot stores need a mount namespace.

Before promoting broader adoption, run the producer and consumer on GitHub,
including a fork pull request, and measure complete cold and warm workflows.
Include Once/Nix installation, evaluation, artifact lookup/download and signature
verification; require reuse to beat rebuilding the representative expensive
check. The synthetic native proof's timings do not establish that workflow result.
HTTPS/S3 backends, signature thresholds, dynamic derivations and additional
platforms remain future work.
